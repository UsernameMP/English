# Техническое задание: Corpus Discovery Network
**Версия:** 0.1 (архитектура для масштабирования; первая реализация — сегмент RU)
**Проект:** Rift / Corpus Engine / Reasoning Data Foundry
**Статус:** базовое ТЗ для разработки, решения с неопределённостью явно обозначены как проектные.
**Первый географический сегмент:** \`RU\` (Россия), с возможностью добавления \`IN\`, \`US\`, \`TR\` и других кодов ISO 3166-1 alpha-2 без изменения схемы.

## 1. Конечный результат и назначение компонента
Целевой продукт — **фабрика проверяемых reasoning-датасетов**. Цепочка:

1. **Discovery Network:** находит сайты, страницы, олимпиады, архивы, ссылки и неизвестные источники.
2. **RAW Acquisition:** надёжно сохраняет оригинальные байты, их SHA-256, происхождение и версии; неизвестная классификация не препятствует сохранению.
3. **Corpus Engine:** реконструирует задачи, связывает условия с ответами/критериями/иллюстрациями и создаёт *структурированный предкорпус*.
4. **Reasoning Factory:** создаёт кандидатов решения, альтернативные стратегии, экспертно валидирует их и отдельно собирает наблюдаемые решения участников.
5. **Verified Dataset:** датасеты задач/знаний/решений с прозрачным происхождением, версиями, правовым статусом и качеством разметки.

**Данное ТЗ относится только к этапам 1–2 и их интерфейсу поиска.** Не смешивать discovery со структурированием задания, Knowledge Atlas, решением задачи или измерением качества reasoning. Не назначать автоматически «решение ученика» тексту решения, созданному ИИ/ассессором.

**Цель прототипа RU:** сделать бесконечно расширяемый, исследуемый каталог первоисточников школьных олимпиад России. При появлении новой олимпиады она должна быть видимой *как кандидат* без ручной правки JSON и без блокировки скачивания RAW. Существующий crawler/parser/Dropbox pipeline не ломать.

## 2. Разделение ответственности
| Подсистема | Отвечает | Не отвечает |
| --- | --- | --- |
| Discovery | Сбор ссылок и свидетельств, кандидаты на сущности, связи, география | Полноценное OCR, задачи, решение, рассуждение |
| Acquisition | Получение оригинала, MIME/magic, SHA-256, версии/зеркала, immutable RAW | Определение олимпиадной сложности |
| Registry/Resolution | Стабильная идентичность и связи с доказательствами; неоднозначности | Насильственное классифицирование неизвестного |
| Corpus Engine | Парсинг, layout, связывание документов/задач/ответов | Поиск новых олимпиад вместо Discovery |
| Reasoning Factory | Эталонные и наблюдаемые трассы, оценка достоверности | Изменение исходных RAW-файлов |
| Read-only Web UI | Исследование сети, поиск, просмотр кандидатов/оригиналов | Запись прямо в GitHub из публичного JavaScript |

## 3. География: принцип «segment.ru»
**Сегмент — независимый поисковый контур, а не язык страницы или домен сайта.** В прототипе \`segment_id = "RU"\`; UI публикуется на \`/English/corpus/ru/\`. В дальнейшем \`/corpus/in/\`, \`/corpus/us/\` и глобальный агрегатор \`/corpus/\`.

Различать:
- \`discovery_segment\`: в рамках какого исследовательского поиска обнаружен источник (\`RU\`).
- \`competition_countries[]\`: страны проведения/организации олимпиады; могут быть несколько, могут быть неизвестны.
- \`source_host_country\`: только подтверждённое размещение/организация ресурса, не выводится из суффикса \`.ru\`.
- \`language_tags[]\`: языки документов (\`ru\`, \`en\`, \`hi\`); язык **не** равен географии.
- \`region_code\`: регион внутри страны (для России — при наличии подтверждённой привязки код региона/субъект, иначе null).
- \`scope\`: local | regional | national | international | unknown, устанавливается по свидетельствам.

**Правила:** (а) российские олимпиады на Google Drive относятся к RU; (б) международный документ может относиться к RU и IN, при этом общий RAW объект хранится один раз; (в) неизвестная страна остаётся неизвестной, не угадывается по URL/IP; (г) добавление страны не создаёт дубликаты файлов и не требует переписывания ID.

Пример: \`segments: ["RU"]\`, \`competition_countries: ["RU","KZ"]\`, \`languages:["ru","en"]\`.

## 4. Модель данных и идентичность
Граф реализуется логически: в MVP его можно материализовать в JSONL + SQLite (без графовой СУБД). Узлы и рёбра имеют стабильные ключи.

### 4.1. Узлы
| Тип | ID и свойства |
| --- | --- |
| DiscoverySegment | \`RU\`; правило включения, период наблюдения, политики обхода |
| SourceSite | канонический origin, алиасы доменов, атрибуты доступности/политики |
| SourcePage | нормализованный URL, время первого/последнего наблюдения, тип HTML/индекса, ETag при наличии |
| Archive/Collection | ссылка на архив, формат (HTML, каталог, папка облака, ZIP), родительские каталоги |
| CompetitionCandidate | наблюдаемое название, версии написания, URL свидетельств, \`candidate\` или \`needs_review\` |
| Competition | стабильная утверждённая идентичность, имена/алиасы, организаторы, география |
| Edition | один выпуск/сезон соревнования, ID без привязки к текстовому названию |
| Round | тур/этап внутри соответствующей олимпиады, исходное локальное название; без глобальной подмены «школьный/муниципальный» |
| MaterialGroup (проектируемый) | свидетельства о комплекте задания/ответы/критерии/аудио; истинные границы уточняет Corpus Engine |
| URLObservation | конкретный URL и факт ссылки/скачивания с timestamp, response status |
| RawAsset | SHA-256 реальных байтов, MIME, размер, immutable Dropbox path, класс доступа и права |

Необязательно создавать Competition/Edition/Round для каждого найденного файла: **неизвестные документы сохраняются** с \`unresolved\` ссылкой.

### 4.2. Рёбра и происхождение
\`DISCOVERED_AT\`, \`LINKS_TO\`, \`HOSTS\`, \`CANDIDATE_FOR\`, \`ALIAS_OF\`, \`INSTANCE_OF\`, \`HAS_ROUND\`, \`HAS_MATERIAL\`, \`OBSERVED_AS\`, \`SAME_BYTES_AS\`, \`REPLACED_BY\`, \`BELONGS_TO_SEGMENT\`.

Каждое утверждение имеет \`evidence_url\`, \`observed_at\`, \`asserted_by\` (rule/model/human), \`confidence\` (опционально), \`decision_state\`: observed | proposed | confirmed | rejected | superseded. Автоматический кандидат не превращается молча в утверждённую идентичность.

### 4.3. Стабильные ID и дубликаты
- RawAsset: \`sha256:<hex>\` (глобальный по всем странам).
- URL observation: ключ URL после безопасной канонизации (удаление fragment, нормализация host/схемы); query-параметры и signed-URL сохранять, если они меняют объект.
- Discovery event: id по \`segment+url+seen_timestamp+discovery_parent\`, идемпотентный ingestion при повторной обработке event_id.
- Competition: непрозрачный стабильный \`cmp_<id>\`; **не** ID из названия/года/страны, позволяющий переименование без миграции.
- Candidate и canonical entity отдельно, возможны many-to-many matching proposals.
- \`SAME_BYTES_AS\` по равным SHA-256 — доказанный дубль; близкий текст/OCR/похожие названия — только предложение о дубликате.
- Один PDF может содержать несколько олимпиад/туров: связи many-to-many, без потери исходника.

### 4.4. Источник истины
В MVP:
- \`registry/competitions.json\` — существующий **утверждённый** каталог (bootstrap), читается без разрушительной миграции;
- \`sources.csv\` — существующая конфигурация краулера (bootstrap); изменения сначала через отдельные Issues/PR;
- \`state/checkpoint.jsonl\` и Dropbox RAW — сохранённый результат текущего краулера, не дублировать в вручную редактируемых справочниках;
- discovery observations/candidates — **машинно создаваемые** JSONL/SQLite, не ручной список;
- \`/corpus/ru/network.json\` и общие JSON views — исключительно вычисляемые статические витрины.

Позднее единственный канонический registry/store может быть SQLite/PostgreSQL; опубликованный формат витрины остаётся стабильным и версионированным. История наблюдений append-only, правки атрибутов — через новые события с ссылкой на предыдущее утверждение.

## 5. Discovery: функциональные требования
**DISC-01.** Начальные корни: каталоги, официальные организаторы, региональные центры, предметные порталы; RU реестр и seed URLs — лишь стартовые точки, не замкнутый whitelist.

**DISC-02.** HTML crawler регистрирует найденные страницы и **внешние ссылки как наблюдения**, даже если не будет переходить по ним немедленно. Текущая same-host политика не должна уничтожать обнаружение внешних ссылок.

**DISC-03.** Следовать по релевантным внешним ссылкам только в границах политики (доменный бюджет/глубина/robots/частота/тип); исключить бесконтрольный обход всего интернета.

**DISC-04.** Адаптеры (позже): HTML/ссылки, Google Drive публичные папки, Яндекс Диск публичные папки, ZIP с безопасным извлечением, каталоги статических PDF, sitemap. Статус \`unsupported_adapter\` фиксируется и виден, не исчезает.

**DISC-05.** Новые имена олимпиад распознавать эвристиками/LLM в режиме гипотез; на первом этапе можно сохранять «unclassified source» и «candidate label», без дорогого обязательного ML.

**DISC-06.** Event ingestion идемпотентен; собирать redirect chain, canonical hint, HTTP status, свидетельство и timestamp; URL и hash raw сохранять без переименования.

**DISC-07.** Разделять факт объявления олимпиады (новость) и доступность заданий. Новость может создавать EditionCandidate, но не «задания найдены».

**DISC-08.** Хранить связи между дубликатами, зеркалами и другими версиями (не перезаписывать старое наблюдение).

**DISC-09.** Границы поиска расширяются по обнаруженным ссылкам и каталогам, при этом метки RU/IN/US могут сосуществовать для одного сайта/файла.

**DISC-10.** Для неизвестной/неразмеченной сущности документ попадает в RAW/очередь, а не отбрасывается по отсутствию \`competition_id\`, \`year\`, \`stage\`.

## 6. Acquisition: функциональные требования
**RAW-01.** Сохранять точные байты файлов, SHA-256, MIME + magic/signature, размер, source URL, discovered_from, attempts, timestamps и Dropbox path.

**RAW-02.** Дедупликация по SHA-256 всех сегментов глобально, URL-версии/зеркала не теряются.

**RAW-03.** Архивы и вложенные файлы: ZIP хранить как оригинал, затем извлекать в отдельные производные assets с \`contained_in\`; ограничения zip-bomb, traversal и лимитов памяти.

**RAW-04.** Сохранять повторные версии по URL, если содержимое изменилось (новый SHA-256). Идемпотентность повторных запусков.

**RAW-05.** Текущие \`/OlympiadCorpus/raw/\`, \`metadata/\`, \`state/checkpoint.jsonl\`, parser state сохраняются без перезаписи/переноса.

**RAW-06.** Для HTML-страницы допустимо сохранять snapshot/хеш и метаданные отдельно от бинарного документа; права и robots соблюдать.

**RAW-07.** Ограничения существующего Dropbox storage: 2 GiB эффективного бюджета в workflow, stop 95%; превышение останавливает *скачивание*, но не факт обнаружения ссылки.

## 7. Registry и автоматическая идентификация
**REG-01.** Новая олимпиада сначала становится \`candidate\` со свидетельством и географией \`RU\` как сегментом обнаружения (не обязательно фактической страной проведения).

**REG-02.** Для известной олимпиады автоматическая привязка только по доказательным признакам (утверждённые alias/source/domain+контекст). Размытое совпадение названий недостаточно.

**REG-03.** Конфликтующие или неоднозначные кандидаты попадают в \`needs_review\`, но это не блокирует RAW.

**REG-04.** Подтверждение осуществляется через GitHub Issue/PR с машинно подготовленным изменением, либо позже через авторизованную консоль; не через публичный GitHub Pages JS.

**REG-05.** Merge/split олимпиады не должен менять RawAsset ID, ссылки и историю provenance.

**REG-06.** Импорт старых \`source_id\` в граф без предположения «один исходный сайт = одна олимпиада».

## 8. Интерфейс RU: три представления, без бессмысленных KPI
**UI-01 «Источники».** Поисковая картотека: сайт → найденные страницы/архивы → связанные олимпиады/кандидаты → известные материалы. Наличие внешнего архива отмечать даже до скачивания файлов.

**UI-02 «Новые находки».** Новые источники, неразобранные ссылки, неопознанные олимпиады, сомнительные merge. Фильтры: subject, name, \`segment=RU\`, год при наличии, confirmed/candidate/unknown. Отображать evidence.

**UI-03 «RAW».** Список оригиналов и альтернативных URL, статус загрузки, SHA, происхождение, коллекция/выпуск, если установлено. Клик открывает URL первоисточника или разрешённую карточку; публичные Dropbox-токены запрещены.

**UI-04.** У каждого объекта собственная карточка с историей discovery и статуса. Unknown — валидное состояние, не пустая или красная «ошибка».

**UI-05.** Навигация \`RU\` как контекст, а не постоянный фильтр предмета «русский язык». Обобщённый multi-segment switch проектировать, но до появления сегмента IN/US не изображать якобы собранные данные.

**UI-06.** Карта «олимпиада × сезон» — необязательное вторичное представление; пустая клетка означает \`not_indexed\`, не доказанное отсутствие задания.

**UI-07.** Данные — статические \`network.json\`, \`coverage.json\`; загрузка fetch, CDN/GitHub Pages; UI **read-only**, без секретов.

**UI-08.** Сохранить действующий \`/English/corpus/\` и Document Triage; новый RU маршрут добавляется параллельно и может стать основной точкой входа после проверки.

## 9. Контракты интеграции
Пример observation (JSONL):
\`\`\`json
{
  "schema_version": "discovery.observation.v1",
  "event_id": "obs_...",
  "segment_id": "RU",
  "source_id": "seed_anokmc",
  "source_page_url": "https://anokmc.ru/olymp",
  "target_url": "https://example.org/archive.pdf",
  "target_kind": "document_candidate",
  "first_seen": "2026-10-11T00:00:00Z",
  "evidence": { "kind": "html_anchor", "text": "Задания", "url": "https://anokmc.ru/olymp" },
  "classification": { "competition_id": null, "status": "unresolved", "asserted_by": "rule" },
  "download": { "status": "PENDING", "sha256": null }
}
\`\`\`

Пример canonical competition:
\`\`\`json
{
  "id": "cmp_...",
  "names": [{"language":"ru","value":"Казанская математическая олимпиада"}],
  "countries": ["RU"],
  "subject_ids": ["mathematics"],
  "stage_taxonomy": [{"id":"qualifier","label":"Отборочный"}],
  "evidence_refs": ["obs_..."],
  "lifecycle": "confirmed"
}
\`\`\`

Пример изолированной публикации:
\`\`\`
/corpus/                         # существующая страница / глобальный вход
/corpus/ru/index.html            # RU: каталог первоисточников
/corpus/ru/network.json          # сгенерированная витрина RU
/corpus/coverage.json            # существующий агрегат (для совместимости)
\`\`\`

Схему публикуемых JSON версионировать. Изменение имен ключей — новая версия, миграция и тесты совместимости. В UI не показывать закрытые секреты, signed links, Dropbox refresh tokens или частные RAW-файлы.

## 10. Ограничения безопасности/прав
- HTTP/HTTPS only; запрет SSRF (localhost, internal/private/link-local IP, cloud metadata); повторная проверка адреса после редиректа и DNS resolution.
- Robots.txt, разумный rate limit, \`User-Agent\`, Retry-After, ограничения глубины/доменов/объёма; платные или авторизованные источники не обходить в нарушение доступа.
- Для хранения данных учитывать лицензию, авторство, разрешённость повторной публикации; доступный документ ≠ право публично переиздавать.
- В GitHub Pages публиковать только безопасные метаданные и публичные URL; RAW не выкладывать автоматически без проверки прав.
- Извлечение контента с подозрительных страниц считать недоверенными данными, а не инструкциями для агента.
- Соблюдать минимизацию персональных данных: объект сбора — материалы олимпиад, не профили участников.

## 11. Нефункциональные требования
- Сеть должна расти до миллионов URL при сохранении stable IDs. MVP может использовать SQLite/JSONL; архитектура не предполагает загрузку миллионов записей в браузер единым файлом.
- При перезапуске discovery и acquisition не терять прогресс; state merge детерминированный.
- Повторное обнаружение того же URL не создаёт повторную RAW-копию, но новая версия байтов учитывается.
- Потери исходников недопустимы при реорганизации имен олимпиад или географии.
- Экспортированный JSON детерминированный при одинаковых данных (кроме явного \`generated_at\`); ссылки проверяются тестами.
- Приложение и существующий Corpus Parser работают без изменений контрактов во время MVP.

## 12. Этапы реализации и GitHub workflow
**Этап 0 — данное ТЗ и Issues:** заморозить контракты границ и последовательность работ. Изменения через GitHub Issue (что/зачем/приёмка) → узкая ветка → коммиты → тесты → Pull Request → main. Мелкие коммиты не подменяют Issues.

**Этап 1 (реализуем сейчас, P0):** сегмент \`RU\`, чистый read-only \`network.json\`, модель фактов и кандидатов на основе существующих 2 704 checkpoint URL + approved registry, страница \`/corpus/ru/\`. Без новых обходов и автоматического утверждения олимпиад.

**Этап 2 (P0):** persistence для page/link observations и unresolved кандидатов; запись внешних ссылок; идемпотентность; мост к существующему downloader без смены Dropbox RAW.

**Этап 3 (P1):** создание кандидата новой олимпиады, имя/страна/организатор/свидетельства, resolution, review посредством PR. Регистр изменяется *один раз* после подтверждения.

**Этап 4 (P1):** ограниченный обход внешних релевантных сайтов, Google/Yandex public-folder adapters, ZIP; оценка безопасности, прав и устойчивости.

**Этап 5 (P2):** связывание Editions/Rounds/MaterialGroups с результатами Corpus Engine; визуальный граф, масштабирование сегментов IN/US и глобальных запросов.

**Не входить в P0:** LLM-рассуждение, автоматический приоритет по «рентабельности» источника, глобальный процент покрытия неизвестного пространства, маркетинговые KPI, изменение Android UI.

## 13. Проверяемая приёмка
- [ ] \`RU\` виден как самостоятельный сегмент; язык документа с ним не смешивается.
- [ ] Из существующего checkpoint строится витрина без потери неопознанных URL (в отдельной коллекции).
- [ ] Зеркала с одним SHA-256 указывают на одну сущность RAW.
- [ ] Один source может ссылаться на несколько CompetitionCandidate/Competition, и наоборот.
- [ ] Неизвестный candidate не блокирует discovery/download; не превращается автоматически в \`confirmed\`.
- [ ] При одинаковом наборе входных наблюдений идентичность узлов/рёбер детерминирована.
- [ ] Разделение внешних URL не приводит к неконтролируемому кросс-доменному обходу.
- [ ] Новый \`/corpus/ru/\` открывается без изменения старого \`/corpus/\` и Document Triage.
- [ ] Проверены пустой корпус, неизвестный год/этап/регион, дубликат URL, одноимённые разные олимпиады.
- [ ] GitHub Actions запускает тесты, не требует ручного редактирования сгенерированных JSON.
- [ ] RAW/checkpoint и parser state остаются совместимыми с существующим \`crawler.py\` и \`parser.py\`.
- [ ] Добавление \`IN\`/ \`US\` — данные/настройка, а не изменение основной схемы.

## 14. Миграции и обратимость
Начальный снимок из Dropbox \`/OlympiadCorpus/state/checkpoint.jsonl\` (2 704 URL на 2026-10-04) — источник наблюдений, но не полный граф мира. Сохранить current checkpoint и старые \`source_id\`; новые поля сегмента добавить **без изменения** существующих ключей в нём. После P0 старая coverage view остаётся доступной. Удаление/объединение графовой сущности выполняется через redirect/supersedes, не physical DELETE для происхождения RAW.

## 15. Открытые решения после первого прототипа
1. Хранилище канонических наблюдений: JSONL в Dropbox + SQLite snapshot или непосредственно SQLite в облаке; в MVP допустим JSONL-снимок в GitHub Pages.
2. Политики междоменных переходов, область сайтов/лицензий, частоты и backoff.
3. Специфика публичных Google Drive/Яндекс папок и допустимые легальные способы доступа.
4. Авторизованный UI утверждения кандидатов: GitHub PR сначала; отдельная консоль при росте.
5. Правила привязки регионов внутри RU и трансграничных олимпиад по документальным свидетельствам.

**Архитектурный инвариант:** никакой этап развития не должен превращать неопределённость метаданных в потерю RAW, а гипотезу — в подтверждённый факт.
